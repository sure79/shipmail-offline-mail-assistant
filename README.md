# ShipMail · 오프라인 조선 전장설계 영어메일 도우미

받은 영어메일 → 문장별 한국어 해석·요청 확인 → 한국어로 회신 작성 → 영어 회신 생성 → 숫자·장비번호·도면 Rev 비교 → 직접 수정 후 복사.
이 모든 과정을 **한 화면에서, 이 PC 안에서만** 처리합니다. GPT·Claude 같은 클라우드 AI나 인터넷 없이, PC에 설치한 로컬 AI 모델(Ollama 또는 LM Studio)을 사용합니다.

> 번역 품질을 보장하지 않습니다. ChatGPT·Claude와 같은 품질이라고 주장하지 않습니다. 최종 검토와 발송은 사용자가 직접 합니다.

---

## 0. 다른 PC에 설치 (GitHub에서 받기)

1. **Python 3.11 이상** 설치 — https://www.python.org/downloads/windows/ ("Add python.exe to PATH" 체크)
2. 이 저장소 받기 — 아래 중 하나
   - 초록색 **Code ▾ → Download ZIP** 후 압축 풀기, 또는
   - `git clone https://github.com/sure79/shipmail-offline-mail-assistant.git`
3. 받은 폴더에서 PowerShell을 열고 실행:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
   ```
   Ollama(약 1.5GB)와 AI 모델(qwen3:8b 약 5.2GB)이 없으면 **받을지 물어본 뒤** 설치합니다. RAM 8GB PC는 `-Model qwen3:4b-instruct-2507-q4_K_M`.
4. 바탕화면 **ShipMail** 아이콘으로 실행 → 브라우저 상단 "qwen3:8b · 로컬 연결됨"

Claude Code가 있으면 폴더를 열고 **"docs/CLAUDE_CODE_SETUP.md 대로 ShipMail을 설치해 줘"** 라고 하면 됩니다.
다른 PC에서 쌓은 용어·예문은 ⚙ 설정 → [전체 백업] JSON을 옮겨 `setup.ps1 -Restore <파일>` 또는 [백업 복원]으로 가져옵니다(업무 문장 포함 — GitHub에 올리지 마세요).

## 2. 사용 방법

1. **왼쪽 · 받은 영어메일**: 원문을 붙여넣습니다. 필요하면 "이전 메일 문맥"에 앞선 대화를 넣습니다. "문장 번호 확인"에서 문장 분리를 확인할 수 있습니다.
2. **한국어로 해석** → **가운데**에 문장별 원문/해석이 나란히 나오고(헷갈리기 쉬운 부정·조건·수량 표현은 **⚠ 주의 표시**), 상대방의 요청·조건/예외·확인 필요 사항이 따로 정리됩니다. 해석은 직접 고칠 수 있습니다.
3. **오른쪽 · 회신 작성**: 전달할 내용을 한국어로 적고 **영어 회신 생성**. 해석을 먼저 하지 않아도 됩니다.
   - 한국어를 그대로 옮기지 않고 **정중하고 자연스러운 업무 영어로 다듬습니다**(인사·배경·요청·맺음 구성, 선급 룰 → Class rules 같은 업계 용어). 사실(숫자·날짜·범위·요청 여부)은 바꾸지 않도록 지시하고 규칙으로 검사합니다.
   - **영어 제목 후보 3개**가 제목 칸 아래 버튼으로 나옵니다. 눌러서 고르고 직접 고칠 수 있습니다.
   - 영어 회신은 **써지는 대로 화면에 바로 보입니다**(회색 기울임 글씨 → 완성되면 정상 글씨). 한국어에 쓴 약어(예: `ES(EMERGENCY STOP)`)는 영어에도 `ES (emergency stop)`처럼 유지합니다.
   - 한국어에 없는 승인·납기·공급 확약·비용·규정 적합성은 추가하지 않도록 지시되어 있습니다.
   - 원문 요청 중 답하지 않은 항목은 "미답변 가능 항목"으로 표시됩니다(자동으로 답을 지어내지 않음).
   - 영작은 **한국어 답변만 보고** 작성하고, 받은 메일은 별도 단계에서 미답변 항목 확인에만 씁니다(원문 문장이 회신에 섞이는 것을 막기 위함).
4. 영어를 직접 고친 뒤 **한국어 뜻 확인**으로 다시 뜻을 봅니다. (검토 보조일 뿐 정확성 증명이 아닙니다)
5. 하단 **중요 정보 교차 확인**: 수량, No.1/No.2, 220V/440V, kW, A, mm, 날짜, 도면 번호, Rev.를 규칙으로 비교하고 부정·의무·조건·승인 표현을 강조합니다. 결과는 "오류 확정"이 아니라 "확인 필요"입니다. 영어를 고친 뒤 **현재 문장 다시 비교**를 누르세요.
6. **제목 + 본문 복사** → 메일 프로그램에 붙여넣어 직접 발송합니다. (자동 발송 기능 없음)

- 원문이나 한국어 답변을 수정하면 기존 결과에 **"이전 입력 기준"** 표시가 붙습니다.
- 처리 중 **취소** 가능, 실패해도 입력은 그대로 남아 같은 버튼으로 재시도합니다.
- 긴 메일은 문맥 단위로 나눠 진행률을 표시하며, 한도 초과 시 **조용히 잘라내지 않고** 안내합니다.
- 글자 크기는 설정에서 14~22px로 조절합니다.

### 빨리 쓰는 요령
- 해석은 **끝난 문장부터 하나씩 표시**됩니다(첫 문장 약 8초). 나온 문장부터 읽고 고치세요.
- 문장이 다 나오고 요약만 남으면 [취소]가 **[요약 건너뛰기]**로 바뀝니다(해석은 유지).
- 다시 해석하면 **바뀐 문장만** AI가 처리하고, 자료실에 저장된 똑같은 문장은 AI 없이 즉시 씁니다.
- 영어 회신은 나오는 즉시 표시되고, 미답변 확인은 뒤이어 채워집니다.
- 앱 화면을 열면 AI 모델을 미리 불러옵니다(30분 유지).

### 쓸수록 좋아지게 하기 (재학습 아님 · 참고 자료 누적)
- **가운데 해석을 고치고 다른 곳을 누르면 자동으로 자료실에 저장**됩니다("✓ 자료실에 저장됨 · 되돌리기" 표시). 이후 **같거나 비슷한 문장**(단어 60% 이상 일치)을 해석할 때 AI가 참고합니다.
- 단어를 바꾸면(예: 창고 → 조선소) 바로 아래 **"용어로도 등록: [영어 단어 ▾] → [조선소] [용어 등록]"** 줄이 나타납니다. 영어 단어만 고르면 용어집(검토 완료)에 들어가 다음 해석부터 적용됩니다.
- **오른쪽 영어 회신을 고치고 다른 곳을 누르거나 [복사]하면** "한국어 답변 → 고친 영어"가 자동 저장되어 비슷한 답변을 영작할 때 참고합니다. 고치지 않은 좋은 회신은 **[이 회신을 예문으로 저장]**으로 저장할 수 있습니다.
- 같은 문장은 중복 저장하지 않고 덮어쓰며, **[되돌리기]**로 바로 취소할 수 있습니다. 자동 저장은 ⚙ 설정에서 끌 수 있습니다(기본 켜짐). 저장 내용에는 메일 문장이 포함되며 로컬 DB에 암호화 없이 저장됩니다.
- 업무 자료실에서 용어를 **"검토 완료"**로 바꾸면(예: cable gland = 케이블 글랜드) 해석·영작 결과에 그 용어가 빠졌을 때 **"용어집 확인"** 경고가 뜹니다.
- 인사말(Dear Sir, Good day), 맺음말(Best regards, Thank you for your cooperation), 맺음말 뒤 서명 줄은 **규칙으로 처리**해 AI에 보내지 않습니다 → 더 빠르고 이름이 음역되지 않습니다(화면에 "규칙으로 처리" 표시).

### 업무 자료실 (왼쪽 메뉴 ▦)
- **전문용어 / 업무 예문 / 프로젝트·호선 / 저장한 메일**을 추가·검색(한국어 부분일치)·수정·삭제.
- JSON/CSV 가져오기(미리보기에서 중복을 보여주고 **건너뛰기/병합** 선택) · 내보내기(CSV 수식 실행 방지 처리).
- 초기 용어 15개, 예문 32개는 모두 **개발자 작성 초안(draft)**입니다. 사람이 **"검토 완료"**로 바꾼 항목 중 메일과 관련된 것만(최대 8개) AI 참고 자료로 전달됩니다. 이는 참고일 뿐 자동 재학습이 아닙니다.
- 프로젝트 메모는 모델에 자동 전달되지 않습니다.

### 저장·백업
- 메일 이력 저장은 **기본 꺼짐**. "이 메일 저장"을 눌렀을 때만 DB에 기록됩니다.
- 임시 자동저장도 **기본 꺼짐**. 켜면 작성 중 내용이 이 PC 브라우저 저장소에만 저장됩니다(암호화 없음).
- 설정 → 전체 백업(JSON 다운로드) / 백업 복원(복원 직전 현재 DB를 `data\backups\`에 자동 백업).
- DB 위치: `data\shipmail.sqlite3` — **암호화되지 않습니다.** 접근이 제한된 로컬 폴더에 두세요. 삭제하려면 앱을 끄고 `data` 폴더를 지우면 됩니다.

## 3. 로컬 AI 모델 선택 (RAM 16GB · RTX 3050 4GB 기준)

RAM과 VRAM은 합산되지 않습니다. 4GB VRAM에 들어가지 않는 부분은 CPU·시스템 RAM으로 처리되어 느려집니다.

| 구분 | 모델 (Ollama 이름) | 파일 크기 | 라이선스 | 비고 |
|---|---|---|---|---|
| 1차 후보 | `qwen3:4b-instruct-2507-q4_K_M` | 약 2.5GB | Apache-2.0 | 비추론(non-thinking) 전용, 100+ 언어. VRAM 4GB에 대부분 적재 기대 |
| 비교 후보 | `gemma3:4b` | 약 3.3GB | Gemma 이용약관 | 140+ 언어. 이미지 기능 포함으로 더 큼 |
| 선택 비교 | `qwen3:8b` 등 7~8B | 약 5GB+ | 모델별 확인 | CPU/GPU 분할로 느려질 가능성 큼 |
| 선택 비교 | `gpt-oss:20b` | 약 14GB | Apache-2.0 | 이 PC에서는 메모리 압박·지연 예상. 기본값 아님 |

(크기·라이선스는 2026-09 ollama.com / Hugging Face 공식 페이지 기준. 반입 전 최신 내용과 회사 정책을 다시 확인하세요.)

- **어떤 모델도 자동 다운로드하지 않습니다.** 위 표는 "후보"이며 실제 평가 전에는 적합하다고 확정하지 않습니다.
- 모델을 바꿔도 화면·DB는 그대로입니다. 설정의 실행 정보에 `GPU에 전부 로드 / CPU/GPU 분할 / CPU로 실행`이 표시됩니다(Ollama, 첫 실행 이후).

### 품질 평가 (반드시 실제 모델로)
```
evaluate.bat --model qwen3:4b-instruct-2507-q4_K_M
```
- `evals\cases.json`: 개발자가 만든 평가 예문 26개 + `evals\realistic.json` 여러 문장 회신 예문 2개(부정/의무, 개별 수량, 예외, 공급 주체, Rev 대체, 첨부 추측 금지, 변경 범위, 승인 날조 금지, 메일 속 지시 무시 등).
- 결과: `evals\results\날짜-모델.md` — 모델명·양자화·런타임 버전·처리 시간·메모리(GPU/CPU)를 기록하고, 각 항목에 **사람 판정** 칸이 있습니다. 자동 힌트는 참고 신호일 뿐 합격 판정이 아닙니다.
- 사용자 실제 메일로 평가하려면 같은 형식의 JSON을 만들고 `"source": "user"`로 표시해 `--cases 파일.json`으로 실행합니다(결과는 개발자 예문과 분리 표시). 결과 파일에는 업무 내용이 들어가므로 외부로 반출하지 마세요.

### 오프라인 점검
와이파이/랜선을 끊고 `offline-check.bat`을 더블클릭하면 ① 인터넷이 정말 끊겼는지 ② 실제 모델로 해석·영작·뜻 확인 ③ 자료실 추가·검색, 백업→복원 ④ ShipMail·Ollama 프로세스의 외부 연결 여부를 점검해 `evals\results\offline-check-*.txt`에 남깁니다. 내 `data` 폴더는 건드리지 않고 임시 DB를 씁니다.
참고: `ollama pull`로 모델을 받는 동안에는 Ollama 서버가 외부에 연결되는 것이 정상입니다.

## 4. LM Studio를 쓰는 경우
LM Studio에서 모델을 받은 뒤 Developer 탭에서 로컬 서버(기본 `127.0.0.1:1234`)를 시작하고, 앱 설정에서 런타임을 **LM Studio 로컬 서버**로 바꾼 다음 모델을 고릅니다. LM Studio 서버 설정에서 "로컬 네트워크에 제공(Serve on Local Network)"은 끄세요. 두 런타임을 모두 설치할 필요는 없습니다.

## 5. 문제 해결

| 증상 | 조치 |
|---|---|
| "Ollama 연결 안 됨" | `start-ollama-local.bat` 실행. 트레이의 Ollama가 이미 돌고 있으면 그대로 사용 가능 |
| "모델을 선택하세요" / "선택 모델이 로컬에 설치되어 있지 않습니다" | ⚙ 설정 → 모델에서 설치된 모델 선택. 목록이 비어 있으면 모델 반입 필요 |
| "메모리 부족" | 다른 프로그램 종료, 더 작은(3~4B, q4) 모델, 컨텍스트 4096으로 축소 |
| "시간 제한을 초과" | CPU 실행 시 느림. 설정의 대기 제한(최대 1800초)을 늘리거나 메일을 나눠 처리 |
| "모델 출력 검증에 실패" | 작은 모델이 형식을 지키지 못함. 입력을 줄여 재시도. 실패 결과는 번역으로 표시하지 않음 |
| 포트 8765 사용 중 | 다른 ShipMail 창 종료, 또는 `py -3 app.py --port 8766` |
| "요청 보호 토큰" 오류 | 앱을 재시작했다면 브라우저 새로고침 |

## 6. 테스트
```
run-tests.bat          (또는  py -3 -m unittest discover -s tests -v)
```
DB 이관/복원, 가져오기 원자성, 외부 엔드포인트 차단, 리디렉션 거부, Host/Origin/토큰 보호, 중요 정보 비교, 입력 보존, 모델 오류(메모리 부족·연결 실패·형식 오류·취소)를 검사합니다. 모델 품질은 이 테스트로 판정하지 않습니다(모의 응답 사용).
